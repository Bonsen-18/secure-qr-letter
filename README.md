# 密语邮简：完全静态的二维码加密信件

## 功能

- 发送方在网页输入正文和暗号，浏览器本地使用 **PBKDF2-HMAC-SHA-256（600,000 次、16 字节随机盐）+ AES-256-GCM（12 字节随机 nonce、128-bit 认证标签）** 加密。
- 二维码实际内容为 `https://你的站点/路径/#m=密文`。密文含版本标记、盐、nonce、加密内容和认证标签，**不含暗号**。
- 接收方扫描二维码后，网页在本地使用相同暗号派生密钥、解密并展示内容。无后台接口、无数据库、无第三方脚本/CDN、无 fetch 请求。
- 支持 PNG 下载、打印、复制链接、错误暗号提醒。

## 最简单的部署方式：GitHub Pages

1. 创建一个公开 GitHub 仓库，例如 `secure-qr-letter`。
2. 将文件 `index.html`、`main.js`、`style.css`、`qr-bundle.js` 上传至仓库根目录（`vendor/` 只是原始代码和许可证备份，运行时不需要上传）。
3. 进入仓库 **Settings → Pages**，选择 **Deploy from a branch**，分支选择 `main`、目录选择 `/(root)`，保存。
4. 等待 GitHub Pages 显示已发布的站点地址，形如 `https://用户名.github.io/secure-qr-letter/`。此处网址是示例，需替换为你的真实地址。
5. 用该 HTTPS 网址打开页面。网址字段会自动填入，然后输入短消息和暗号，点击“加密并生成二维码”。
6. 下载 PNG 或直接打印；**先用另一部手机试扫**，确认扫码打开页面、能用暗号解密，再邮寄。

也可以使用 Cloudflare Pages / Netlify 等静态托管服务。**上传的是网页代码，不是密文或暗号。**

## 本地开发

```bash
cd secure-qr-letter
python3 -m http.server 8000
```

浏览器打开 `http://localhost:8000/`。大多数现代浏览器允许 localhost 使用 Web Crypto，但二维码需要一个真正可被收件人访问的 HTTPS 公网域名，因此本地开发时不能直接生成可邮寄的二维码。

## 安全说明与限制

- 暗号必须通过**另一条可信渠道事先约定**；建议 5~6 个以上随机词组成的口令，或安全生成的长随机字符。12 位是最短输入限制，不代表任意 12 位暗号都有足够安全性。低熵口令可被获取密文的人离线猜解。
- 二维码是**公开且可复制**的，任何拿到它的人都能保存密文、尝试猜暗号。本项目不具备撤回、阅后即焚、防截图、防转发、收件人身份认证能力。
- 网址中的 `#` 片段正常不会发到 HTTPS 服务器，但可能被浏览器历史、截图、设备同步、分享扩展或恶意浏览器插件读取；仅在可信设备上使用。
- 静态托管服务仍可在将来修改所提供的解密网页代码；若担心站点被篡改，需要自托管、审查代码或采取其他代码完整性保护。
- 为保证打印后可扫描，本项目将二维码 URL 限制在约 1700 字符以内。中文占用 UTF-8 字节多，适合短消息，不适合长篇信件与图片。打印至少 7–10 cm 见方，高密度二维码应更大；每次先实测扫码。
- 不主动在任何服务器存储信件，但扫码访问 HTTPS 站点时，站点服务商仍可能看到访问 IP、时间等元数据。
- 接收方访问站点需要联网；本地输入加解密在页面加载后无需联网。二维码本身必须用可公开访问的站点地址。
